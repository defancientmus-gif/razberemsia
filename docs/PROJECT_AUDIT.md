# Разберемся: аудит проекта и карта развития

Дата: 2026-05-17

## 1. Что это за проект

`Разберемся` - мобильный PWA-помощник для заметок, мыслей, напоминаний и мягкого саморазбора.

Главная идея: не просто хранить текст, а помогать человеку превращать хаос мыслей в ясные маленькие действия без давления, суеты и "продуктивной" агрессии.

Текущий продукт уже имеет:

- мобильный HTML/PWA-интерфейс;
- вход через Supabase email OTP;
- облачную синхронизацию пользовательского состояния;
- локальное хранение в `localStorage`;
- заметки, корзину, историю, быстрые записи;
- категории и простое локальное распознавание смысла заметки;
- голосовой ввод через Web Speech API;
- service worker и manifest;
- черновую AI-панель анализа заметки через Supabase Edge Function.

## 2. Текущая архитектура

### Клиент

Главный файл:

- `index.html`

Он содержит:

- разметку;
- стили;
- клиентскую логику;
- Supabase auth;
- CRUD заметок;
- PWA/уведомления;
- AI UI.

Это быстро для прототипа, но файл уже стал слишком большим. Следующий этап - не обязательно переписывать на React, но нужно начать отделять смысловые зоны.

### Supabase

Файл:

- `supabase.sql`

Таблица:

- `public.user_state`

Поля:

- `user_id`
- `notes`
- `trash`
- `history`
- `name`
- `updated_at`

RLS включен, политики ограничивают доступ владельцем строки через `auth.uid() = user_id`.

### AI

Файл:

- `supabase/functions/ai/index.ts`

Функция принимает:

```json
{
  "action": "analyze",
  "payload": {
    "text": "текст заметки"
  }
}
```

Проверяет Supabase JWT, вызывает Anthropic Messages API и возвращает:

```json
{
  "summary": "суть заметки",
  "tags": ["тег"],
  "actions": ["действие"]
}
```

Важно: AI сейчас только предлагает разбор. Он не меняет заметку автоматически.

## 3. Главные риски

### 3.1. Один большой `index.html`

Риск: любой новый слой будет сложнее добавлять без регрессий.

Что делать:

- держать `index.html` как основной runtime, но выносить документацию и крупные будущие модули в отдельные файлы;
- перед любым крупным изменением фиксировать, какой экран и какие функции затрагиваются;
- не переписывать все сразу.

### 3.2. AI без сохранения контекста

Риск: помощник будет давать одноразовые общие советы.

Что делать:

- добавить модель пользовательского контекста;
- хранить AI-результаты отдельно от исходного текста;
- фиксировать, что пользователь принял, отклонил или изменил.

### 3.3. Секреты

Риск: нельзя класть AI API key в HTML.

Текущее решение правильное: Anthropic key ожидается в Supabase Edge Function secret.

### 3.4. PWA cache

Риск: GitHub Pages может показывать старый `index.html` из service worker/cache.

Что делать:

- при изменении PWA повышать cache version в `sw.js`;
- после деплоя проверять в private window или очищать site data.

## 4. Чеклист ближайших работ

### Деплой и инфраструктура

- [ ] Убедиться, что локальная папка является git-репозиторием или работать через чистый clone.
- [ ] Проверить, что GitHub Pages смотрит на `main`.
- [ ] После каждого деплоя сравнивать `GitHub main index.html` и опубликованную Pages-версию.
- [ ] Добавить Supabase Edge Function `ai`.
- [ ] Установить secret `ANTHROPIC_API_KEY`.
- [ ] При необходимости установить secret `ANTHROPIC_MODEL`.

### Безопасность

- [ ] Выполнить `supabase.sql` в Supabase SQL editor.
- [ ] Проверить RLS на `user_state`.
- [ ] Проверить, что anon/publishable key есть только в клиенте, а service role/AI keys нигде не опубликованы.
- [ ] Не отправлять заметки в AI без авторизованной сессии.
- [ ] Добавить лимиты на AI-запросы.

### AI-помощник

- [ ] Расширить ответ AI: `type`, `summary`, `tags`, `actions`, `reminderCandidate`, `question`, `confidence`.
- [ ] Добавить кнопки: применить теги, создать напоминание, добавить действия в список.
- [ ] Сохранять AI-разбор в заметку только после согласия пользователя.
- [ ] Добавить пользовательский профиль помощи.
- [ ] Добавить "не делать": не морализировать, не выдумывать, не давить.

### Продукт

- [ ] Сохранить мягкий тон и ощущение спокойного помощника.
- [ ] Сделать быстрый сценарий: записал мысль -> получил ясность -> выбрал одно действие.
- [ ] Не превращать приложение в тяжелый таск-менеджер.
- [ ] Развивать "город недели" как отдельный экспериментальный прототип, не смешивая его раньше времени с основным PWA.

## 5. Принципы развития

1. Сначала безопасность и сохранность заметок.
2. Потом структурный AI-разбор.
3. Потом контекст и память.
4. Потом планирование и игровые метафоры.
5. Любая автоматизация должна быть подтверждаемой пользователем.

## 6. Определение качества помощника

Хороший помощник в `Разберемся`:

- понимает заметку, но не делает вид, что знает больше текста;
- предлагает маленькие действия;
- задает один точный вопрос, если нужна ясность;
- сохраняет тон бережный и взрослый;
- не превращает жизнь пользователя в список KPI;
- помогает увидеть смысл и следующий шаг.
