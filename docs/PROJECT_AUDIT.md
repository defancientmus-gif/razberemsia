# Разберёмся — аудит проекта и карта развития

Дата: 2026-05-17

## 1. Что это за проект

`Разберёмся` — мобильный PWA-помощник для заметок, мыслей, напоминаний, цифровой грамотности и мягкого саморазбора.

Главная идея: не просто хранить текст, а помогать человеку превращать хаос мыслей в ясные маленькие действия без давления, суеты и «продуктивной» агрессии.

Следующее ядро продукта — ультраадаптивный чат, который обучает человека пользоваться заметками, чатом, интернетом и AI прямо в процессе записи.

## 2. Что уже есть

- мобильный HTML/PWA-интерфейс;
- GitHub Pages деплой;
- вход через Supabase email OTP;
- облачная синхронизация пользовательского состояния;
- локальное хранение в scoped `localStorage`;
- заметки, корзина, история, быстрые записи;
- чат-лента заметок;
- открытие заметки по клику;
- открытие новой заметки по клику на пустую ленту;
- категории и простое локальное распознавание смысла заметки;
- голосовой ввод через Web Speech API;
- service worker и manifest;
- AI-панель анализа заметки через Supabase Edge Function.

## 3. Текущая архитектура

### Клиент

Главный файл:

- `index.html`

Он содержит:

- разметку;
- стили;
- клиентскую логику;
- Supabase auth;
- CRUD заметок;
- PWA/уведомления;
- AI UI.

Файл большой. Это нормально для текущего MVP, но риск растёт.

### Supabase

Файл:

- `supabase.sql`

Таблица:

- `public.user_state`

Поля:

- `user_id`
- `notes`
- `trash`
- `history`
- `name`
- `updated_at`

RLS включён, политики ограничивают доступ владельцем строки через `auth.uid() = user_id`.

### AI

Локальный файл функции:

- `supabase/functions/ai/index.ts`

Frontend endpoint сейчас:

- `https://izvwgyudjbxlixzrgpuv.supabase.co/functions/v1/smooth-processor`

Функция принимает:

```json
{
  "action": "analyze",
  "payload": {
    "text": "текст заметки"
  }
}
```

Проверяет Supabase JWT, вызывает Anthropic Messages API и возвращает:

```json
{
  "summary": "суть заметки",
  "tags": ["тег"],
  "actions": ["действие"]
}
```

Важно: AI сейчас только предлагает разбор. Он не меняет заметку автоматически.

## 4. Оценка адаптивного AI-чата

Идея сильная и стратегически центральная.

Почему:

- она делает проект не просто заметками, а помощником цифровой уверенности;
- обучение происходит незаметно, в момент реального действия;
- AI получает понятную роль: помогать человеку формулировать, понимать, искать, планировать;
- можно развивать персонализацию без сложного интерфейса;
- это хорошо сочетается с аудиторией проекта.

Главный риск:

- подсказки могут стать шумом и начать раздражать.

Антидот:

- одна подсказка за раз;
- короткий текст;
- кнопка «не надо»;
- учёт отказов;
- AI не правит текст без согласия;
- уровень помощи меняется по поведению человека.

## 5. Главные риски

### 5.1. Один большой `index.html`

Риск: любые новые слои сложнее добавлять без регрессий.

Что делать:

- держать `index.html` как основной runtime до стабилизации MVP;
- перед крупной правкой фиксировать зону: auth, storage, notes, sheet, AI, PWA;
- не переписывать всё сразу.

### 5.2. AI без памяти

Риск: помощник будет давать одноразовые общие советы.

Что делать:

- хранить AI-разборы отдельно от исходного текста;
- фиксировать, что пользователь принял, отклонил или изменил;
- постепенно строить профиль уровня помощи.

### 5.3. Секреты

Риск: нельзя класть AI API key в HTML.

Текущее правильное решение:

- Anthropic key хранится в Supabase Edge Function secret `ANTHROPIC_API_KEY`.

### 5.4. PWA cache

Риск: GitHub Pages может показывать старый `index.html` из service worker/cache.

Что делать:

- при изменении PWA повышать cache version в `sw.js`;
- после деплоя сравнивать хеш локального и опубликованного `index.html`;
- открывать с query cache-buster;
- при необходимости очищать site data.

### 5.5. Несовпадение имени Edge Function

Риск: локальный файл называется `supabase/functions/ai/index.ts`, а frontend endpoint сейчас `/smooth-processor`.

Что делать:

- считать frontend endpoint источником факта для текущего сайта;
- в Supabase Dashboard проверить, какая функция реально обслуживает `/smooth-processor`;
- привести имена к одному виду позже, без ломки рабочего сайта.

### 5.6. Разные пути на Mac и Windows

Риск: AI или человек начнёт считать абсолютный путь частью проекта и путаться между `/Users/...` и `C:\...`.

Что делать:

- считать источником правды repo root, а не абсолютный путь;
- использовать относительные пути от корня repo;
- синхронизировать Mac и Windows через GitHub;
- не добавлять в код абсолютные пути конкретной машины;
- перед работой на любой машине делать `git pull`, после работы commit/push.

## 7. Определение качества помощника

Хороший помощник в `Разберёмся`:

- понимает заметку, но не делает вид, что знает больше текста;
- предлагает маленькие действия;
- задаёт один точный вопрос, если нужна ясность;
- сохраняет тон бережный и взрослый;
- не превращает жизнь пользователя в список KPI;
- помогает увидеть смысл и следующий шаг;
- мягко обучает пользоваться цифровыми инструментами;
- умеет отступить, если подсказка не нужна.
