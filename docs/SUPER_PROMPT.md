# Супер-промт проекта "Разберемся"

Используй этот промт как сжатый контекст для Claude, Codex или другого AI-редактора проекта.

---

Ты работаешь над проектом `Разберемся`.

## Суть проекта

`Разберемся` - мобильный PWA-помощник для заметок, мыслей, напоминаний и мягкого саморазбора.

Это не просто блокнот и не жесткий таск-менеджер. Это спокойный личный помощник, который помогает человеку превратить внутренний шум в ясность, маленькие действия и бережный план.

Философия продукта:

- меньше давления, больше ясности;
- меньше "стань продуктивнее", больше "давай разберемся";
- не морализировать;
- не выдумывать;
- не подменять человека;
- помогать видеть следующий маленький шаг;
- сохранять ощущение теплого, тихого, взрослого помощника рядом.

## Текущее состояние

Основной файл приложения:

- `index.html`

Это большой автономный HTML/PWA, где находятся:

- интерфейс;
- стили;
- логика заметок;
- Supabase auth;
- синхронизация;
- PWA;
- уведомления;
- голосовой ввод;
- AI-панель.

Supabase:

- вход через email OTP, не magic link;
- пользователь вводит почту;
- получает 6-значный код;
- код проверяется через `sb.auth.verifyOtp`;
- пользовательское состояние хранится в `public.user_state`.

Таблица `user_state`:

- `user_id`
- `notes`
- `trash`
- `history`
- `name`
- `updated_at`

RLS должен быть включен. Пользователь может читать и писать только строку, где `auth.uid() = user_id`.

AI:

- клиент вызывает Supabase Edge Function `/functions/v1/ai`;
- функция лежит в `supabase/functions/ai/index.ts`;
- Anthropic API key хранится только в Supabase secrets;
- AI сейчас анализирует текст заметки и возвращает `summary`, `tags`, `actions`.

## Текущий AI-поток

1. Пользователь открывает редактор заметки.
2. Пишет текст.
3. Нажимает `AI`.
4. Клиент берет Supabase access token.
5. Клиент отправляет:

```json
{
  "action": "analyze",
  "payload": {
    "text": "текст заметки"
  }
}
```

6. Edge Function проверяет пользователя через Supabase JWT.
7. Edge Function отправляет заметку в Claude.
8. Claude возвращает JSON.
9. Клиент показывает:

- суть;
- теги;
- возможные действия.

Важно: AI не должен автоматически менять заметку без согласия пользователя.

## Правила разработки

При любых изменениях:

1. Не ломай Supabase email OTP.
2. Не возвращай Firebase, SMS или локальный dev-login.
3. Не клади Anthropic/OpenAI/API secrets в `index.html`.
4. Не отключай RLS.
5. Не делай AI-ответы свободным markdown, если UI ждет JSON.
6. Не переписывай весь проект на новый фреймворк без отдельного решения.
7. Не ломай мобильный UX.
8. Не усложняй интерфейс ради "умности".

## Как должен вести себя AI-помощник

AI в `Разберемся` должен:

- говорить по-русски;
- быть спокойным и конкретным;
- возвращать структурированные данные;
- отделять факт от предположения;
- не ставить диагнозы;
- не давать категоричных медицинских/юридических/финансовых советов;
- задавать уточнение, если заметка непонятна;
- предлагать 1-3 маленьких действия;
- уважать, что заметка может быть просто мыслью, а не задачей.

Идеальный формат будущего ответа:

```json
{
  "type": "task | event | thought | health | contact | purchase | idea | list | other",
  "summary": "короткая суть",
  "tags": ["тег1", "тег2"],
  "actions": ["маленькое действие 1", "маленькое действие 2"],
  "reminderCandidate": null,
  "question": "один уточняющий вопрос или null",
  "confidence": 0.82
}
```

## Куда развивать продукт

Ближайшая цель:

Сделать AI не "чатом обо всем", а редактором заметок, который помогает разобрать конкретную запись.

Следующие шаги:

1. AI-анализ заметки.
2. Применение тегов по кнопке.
3. Предложение напоминания по кнопке.
4. Превращение действий в чеклист.
5. Сохранение AI-разбора в заметку.
6. Пользовательский профиль контекста.
7. История принятых/отклоненных AI-предложений.
8. Недельное планирование.
9. Игровой город как отдельная метафора планирования.

## Контекст, который нельзя потерять

Проект не про "еще один todo app".

Проект про ощущение:

> Мне не надо держать все в голове. Я могу записать как есть, а приложение спокойно поможет разложить это по полочкам.

Любая новая функция должна проходить проверку:

- она снижает тревогу или добавляет шум?
- она помогает понять следующий шаг?
- она сохраняет человеческий тон?
- она не делает вид, что знает жизнь пользователя лучше самого пользователя?
- она работает на телефоне быстро и понятно?

## Технический чеклист перед ответом

Перед тем как предлагать или делать изменение:

- прочитай `PROJECT_CONTEXT.md`;
- проверь `MASTER.md`;
- проверь `supabase.sql`;
- найди затрагиваемые функции в `index.html`;
- если изменение связано с AI, проверь `supabase/functions/ai/index.ts`;
- после правок проверь синтаксис JS/TS;
- убедись, что секреты не попали в клиент.
