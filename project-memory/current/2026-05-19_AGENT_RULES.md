# Разберёмся — Agent Rules

Последнее обновление: 2026-05-19

## Рабочий порядок

1. Сначала читать `project-memory/README.md`, `current/2026-05-19_PROJECT_BRIEF.md`, `current/2026-05-19_TODO.md`.
2. Проверить `git status --short --branch`.
3. Не трогать чужие/untracked изменения без прямой просьбы.
4. Для поиска использовать `rg` / `rg --files`.
5. Перед крупной документальной чисткой делать zip-бэкап.

## Границы

- Если задача про документы/промты — не менять runtime.
- Если задача про код — не менять картинки, иконки и визуальные ассеты без прямого запроса.
- Не делать “улучшения заодно”.
- Не переписывать продуктовую концепцию без согласия пользователя.
- Не удалять контекст; устаревшее переносить в архив или сжимать.

## Supabase и данные

- Не просить и не использовать `service_role` key в клиенте.
- Не отключать RLS.
- Не класть Anthropic/OpenAI/API keys в клиент.
- Все AI-запросы идут через Supabase Edge Function.
- Перед schema-dependent правкой: сначала миграция или обратная совместимость, потом клиент.
- После изменений в Supabase-контуре проверять живой сценарий: вход -> загрузка заметок -> новая заметка -> обновление -> заметка осталась.

## PWA

- При изменении `index.html`, `js/app.js`, `sw.js` или ассетов, которые кэширует service worker, повышать cache name в `sw.js`.
- После пуша проверять PWA/страницу на старый кэш.
- Не считать “работает локально” достаточной проверкой для PWA.

## Проверки перед пушем

Минимум для frontend:

```bash
node --check js/app.js
```

Если менялся `index.html`, проверить inline-скрипты:

```bash
node -e "const fs=require('fs'),vm=require('vm');const html=fs.readFileSync('index.html','utf8');let i=0;for(const m of html.matchAll(/<script(?![^>]*src=)[^>]*>([\s\S]*?)<\/script>/gi)){i++;new vm.Script(m[1],{filename:'inline script '+i});console.log('inline script '+i+': ok')}"
```

Минимум для продукта:

- вход виден;
- облако не падает;
- заметка создаётся;
- после обновления заметка остаётся.

## Ошибки, которые нельзя повторять

- Нельзя выкатывать клиент, который требует новую колонку Supabase, пока колонка не создана или нет fallback.
- Нельзя ради AI-памяти ломать загрузку заметок.
- Нельзя менять UI/картинки, если задача была про память/промты/документы.

## Роль AI-партнёра

AI здесь нужен не для самодеятельности, а чтобы человек без dev-образования мог воплощать фантазии в рабочий продукт. Последовательность, проверки и защита базового сценария — ответственность ассистента.
