# Супер-промт проекта «Разберёмся»

Используй этот текст как сжатый контекст для Claude, Codex или другого AI-редактора проекта.

## Коротко

Ты работаешь над проектом `Разберёмся`.

Это PWA-помощник для заметок, мыслей, напоминаний и цифровой поддержки людей, которым тревожно или непонятно пользоваться технологиями.

Одна строка идеи:

> Ультраадаптивный чат учит человека пользоваться заметками, чатом, интернетом и AI через короткие подсказки прямо в момент записи, подстраиваясь под уровень человека и помогая делать следующий маленький шаг.

## Философия

Это не просто блокнот и не жёсткий таск-менеджер. Это спокойный личный помощник, который помогает человеку превратить внутренний шум в ясность, маленькие действия и бережный план.

Принципы:

- меньше давления, больше ясности;
- меньше «стань продуктивнее», больше «давай разберёмся»;
- не морализировать;
- не выдумывать;
- не подменять человека;
- помогать видеть следующий маленький шаг;
- обучать без ощущения школы;
- сохранять тёплый, взрослый, спокойный тон.

## Текущее состояние

Основной файл приложения:

- `index.html`

Публичный сайт:

- `https://defancientmus-gif.github.io/razberemsia/`

Текущий интерфейс:

- `v4.13`

Service worker:

- `sw.js`, cache `rz-v60`

Supabase:

- вход через email OTP, не magic link;
- пользователь вводит почту;
- получает 6-значный код;
- код проверяется через `sb.auth.verifyOtp`;
- пользовательское состояние хранится в `public.user_state`.

Таблица `user_state`:

- `user_id`
- `notes`
- `trash`
- `history`
- `name`
- `updated_at`

RLS должен быть включён. Пользователь может читать и писать только строку, где `auth.uid() = user_id`.

AI:

- клиент вызывает Supabase Edge Function;
- текущий frontend endpoint: `/functions/v1/smooth-processor`;
- локальный код функции лежит в `supabase/functions/ai/index.ts`;
- Anthropic API key хранится только в Supabase Secrets как `ANTHROPIC_API_KEY`;
- AI сейчас анализирует текст заметки и возвращает `summary`, `tags`, `actions`;
- клиент подмешивает `memoryContext` из локальной `rz_ai_memory`;
- AI-теги кликабельны, а под тегами есть быстрый пикер раздела.

Known issue: в текущей версии после нажатия `✦ AI` может появиться `Can't find variable: autoLabel`. Причина уже найдена: `autoLabel` объявлен внутри блока `if(tags?.length)`, а ниже используется при сборке пикера раздела. Не делать большой рефакторинг ради этого: нужен маленький scoped fix.

## Пути

Проект может быть открыт на Mac и Windows. Не опирайся на абсолютный путь.

Считай корнем проекта папку git-репозитория `razberemsia`.

Используй относительные пути:

- `index.html`
- `sw.js`
- `manifest.json`
- `supabase.sql`
- `supabase/functions/ai/index.ts`
- `docs/SUPER_PROMPT.md`

Mac-путь и Windows-путь могут отличаться. Это не конфликт, если файлы синхронизируются через GitHub.

## Текущий AI-поток

1. Пользователь открывает редактор заметки.
2. Пишет текст.
3. Нажимает `✦ AI`.
4. Клиент берёт Supabase access token.
5. Клиент отправляет:

```json
{
  "action": "analyze",
  "payload": {
    "text": "текст заметки",
    "memoryContext": ["короткая выжимка прошлой заметки"]
  }
}
```

6. Edge Function проверяет пользователя через Supabase JWT.
7. Edge Function отправляет заметку в Claude.
8. Claude возвращает JSON.
9. Клиент показывает суть, теги и действия.

Важно: AI не должен автоматически менять заметку без согласия пользователя.

## Следующая версия AI-ответа

Нужно развивать AI не в сторону «чат обо всём», а в сторону адаптивного редактора и наставника внутри заметок.

На первых этапах достаточно простой и дешёвой модели, если она стабильно возвращает структурированный JSON и помогает понять механику. Не надо ждать идеального адаптивного интеллекта. Сначала запусти рабочий контур: заметка -> анализ -> суть/теги/действия -> мягкая подсказка. Потом улучшай промт, модель и память.

Рекомендуемый старт:

```ts
model: "claude-haiku-4-5-20251001"
```

Более сильные модели вроде Sonnet использовать позже, когда станет понятно, какие подсказки реально полезны.

Желаемый формат:

```json
{
  "type": "task | event | thought | question | internet_help | account_help | health | contact | purchase | idea | list | other",
  "level": "beginner | normal | confident",
  "summary": "короткая суть",
  "microHint": "одна мягкая подсказка по использованию чата/заметки",
  "tags": ["тег1", "тег2"],
  "actions": ["маленькое действие 1", "маленькое действие 2"],
  "reminderCandidate": null,
  "question": "один уточняющий вопрос или null",
  "confidence": 0.82,
  "safety": "ok | caution | urgent"
}
```

## Как должен вести себя AI

AI в `Разберёмся` должен:

- говорить по-русски;
- быть спокойным и конкретным;
- возвращать структурированные данные;
- отделять факт от предположения;
- не ставить диагнозы;
- не давать категоричных медицинских/юридических/финансовых советов;
- задавать один уточняющий вопрос, если заметка непонятна;
- предлагать 1-3 маленьких действия;
- уважать, что заметка может быть просто мыслью;
- помогать пользователю учиться писать, спрашивать и искать лучше;
- учитывать уровень пользователя;
- не стыдить за ошибки, короткие фразы и сумбур.

## Микроблок в чат-заметке

Пример:

```text
Похоже, это дело на завтра.
Можно поставить мягкое напоминание или превратить в чеклист.

[Напомнить] [Сделать чеклист] [Не надо]
```

Микроблок должен быть коротким. Не показывать сразу много советов.

## AI-память и кластеры

Будущая память ассистента должна быть облаком смыслов.

Не хранить всё как один огромный чат. Делить минимум на два кластера:

1. Личный кластер:
   - планы;
   - покупки;
   - здоровье;
   - семья;
   - тревоги;
   - идеи;
   - напоминания.

2. Проектный кластер:
   - заметки о развитии `Разберёмся`;
   - баги;
   - решения и причины решений;
   - Supabase/Auth/AI-настройки;
   - UX-выводы;
   - промты;
   - задачи по улучшению кода.

Проектный кластер нужен, чтобы пользователь мог писать рабочие мысли прямо в заметках, а ассистент помогал превращать их в TODO, changelog, архитектурные решения и будущие правки.

Ассистент — не Джарвис. Он друг, планировщик, напоминалка и соавтор проекта.

Стоимость держать низкой: хранить summaries, отправлять в запрос только релевантные выжимки, использовать Haiku 4.5 для обычного анализа.

## Правила разработки

При любых изменениях:

1. Не ломай Supabase email OTP.
2. Не возвращай Firebase, SMS или локальный dev-login.
3. Не клади Anthropic/OpenAI/API secrets в `index.html`.
4. Не делай прямой вызов `api.anthropic.com` из браузера.
5. Все AI-запросы только через Supabase Edge Function.
6. Не отключай RLS.
7. Не делай AI-ответы свободным markdown, если UI ждёт JSON.
8. Не переписывай весь проект на новый фреймворк без отдельного решения.
9. Не ломай мобильный UX.
10. Не усложняй интерфейс ради «умности».

## Исходы ошибок

- Нет сессии: попросить войти.
- Текст короткий: попросить написать чуть больше.
- `ANTHROPIC_API_KEY` не настроен: чинить Supabase Secrets, не frontend.
- Edge Function не найдена: проверить имя endpoint и деплой функции.
- Claude вернул не JSON: обработать в функции и вернуть понятную ошибку.
- Нет сети: не терять заметку, AI попробовать позже.
- Старый PWA cache: повысить `rz-vXX`, открыть с cache-buster или очистить site data.

## Куда развивать продукт

Ближайшая цель:

Сделать AI не «чатом обо всём», а адаптивным редактором заметок и цифровым наставником.

Следующие шаги:

1. Починить/настроить Supabase secret `ANTHROPIC_API_KEY`.
2. Поставить рабочую модель, например `claude-haiku-4-5-20251001`.
3. Получить первый успешный ответ AI в интерфейсе.
4. Расширить JSON-ответ AI.
5. Показать микроблок подсказки в редакторе.
6. Применять теги по кнопке.
7. Предлагать напоминание по кнопке.
8. Превращать действия в чеклист.
9. Сохранять AI-разбор только после согласия.
10. Собирать контекст принятых/отклонённых подсказок.
11. Постепенно обучать человека пользоваться чатом, заметками и интернетом.
12. Потом развивать игровой город недели как отдельную метафору планирования.

## Контекст, который нельзя потерять

Проект не про «ещё один todo app».

Проект про ощущение:

> Мне не надо держать всё в голове. Я могу записать как есть, а приложение спокойно поможет разложить это по полочкам и научит пользоваться цифровыми инструментами без стыда.

Любая новая функция должна проходить проверку:

- она снижает тревогу или добавляет шум?
- она помогает понять следующий шаг?
- она сохраняет человеческий тон?
- она не делает вид, что знает жизнь пользователя лучше самого пользователя?
- она работает на телефоне быстро и понятно?
