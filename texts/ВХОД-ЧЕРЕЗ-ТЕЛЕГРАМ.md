**Поправка 18.11 — второй заход (щит клиента вырос до 20 проверок).** В `initAuth` вход
по подписи стоял под `else if(!CU)`, а `enterUser` пишет `rz_last_user`. На втором запуске

настоящий `initAuth` из `js/app.js` в двух сценариях (кэш пуст / кэш есть, сессия истекла),
а не только модуль `js/tg-auth.js` — прежний до этой ветки не доставал и молчал.
Проверено на сломе: `else if(!CU)` → exit 1.

### Как устроен вход (коротко)

1. Телеграм отдаёт странице `Telegram.WebApp.initData` — строку с подписью `hash`.
2. Клиент шлёт её на Edge Function действием `tg_auth` (телом запроса, не в адресе).
3. Сервер считает `secret = HMAC_SHA256(key="WebAppData", msg=токен_бота)`,
   затем `HMAC_SHA256(key=secret, msg=строка_полей)` и сверяет с `hash`.
   Поля — все, кроме `hash`, отсортированы, через `\n`. `signature` (Ed25519-подпись
   Bot API 7+) **остаётся** в строке: телеграм считает `hash` по строке, где он уже есть.
   Выкинуть его — значит отклонять живой вход; проверено на образце соседа
   (`Телеграм/miniapp.py`, в проде с 05.11 — там снимается только `hash`).
4. Сошлось → сервер заводит/находит человека по почте `tg<id>@tg.razberemsia.local`
   (пароль выводится из токена бота, наружу не уходит) и отдаёт сессию Supabase.

Подпись живёт сутки (`auth_date`); старше — отказ. `initDataUnsafe` не используется:
его телеграм не подписывает, доверять нельзя.

## Что осталось — руки Жени (без них вход не включится)

Нужны **два секрета** в Supabase → Project Settings → Edge Functions → Secrets
(или `supabase secrets set`):

1. `TELEGRAM_BOT_TOKEN` — токен бота, чью кнопку меню будем вести на приложение.
   Без него `tg_auth` отвечает 503 «не настроен», и всё работает по-старому.
2. `SUPABASE_SERVICE_ROLE_KEY` — обычно уже подставляется автоматически;
   если нет — добавить (он **не** уходит в клиент, живёт только в секретах).

Дальше — выкладка Edge Function (**отдельно** от фронта, это не делает `deploy.sh`):

```bash
cd ~/Documents/Разберемся
supabase functions deploy ai --no-verify-jwt
```

И последняя миля — чтобы кнопка появилась у людей (его руками, BotFather):

- BotFather → нужный бот → `/setmenubutton` → адрес `https://defancientmus-gif.github.io/razberemsia/`
  (или `/mybots` → Bot Settings → Menu Button). Можно и через `setChatMenuButton`.
- Телеграм открывает Mini App только из кнопки/ссылки вида `t.me/бот/app` —
  простой адрес в браузере подписи не даёт, это по спеке телеграма.

### Что решить за него (я решил сам, откат дешёвый)

- **Почта-заглушка, а не отдельная таблица.** Человек из телеграма получает
  `tg<id>@tg.razberemsia.local`. Так заметки лежат в той же `user_state`, что и у всех,
  и не нужна новая сущность (конституция §4). Переиграть: сменить `почтаДляТг()`.
- **Тот же бот или новый.** Код не зависит от того, какой бот даст токен: подпись
  проверяется любым токеном. Если у бота «Заметки» (Динеш) уже есть кнопка меню —
  можно взять его токен и получить вход даром.
- **Свой адрес в `js/tg-auth.js`, не из `app.js`.** Файл грузится раньше `app.js`,
  где адрес объявлен через `const` — обращение к нему на загрузке даёт ReferenceError
  (мёртвая зона `const`). Свой адрес снимает ловушку целиком.

1. Секреты поставлены → `curl` на функцию действием `tg_auth` с пустым `initData`

2. Женя открывает бота → кнопка меню → приложение открывается уже внутри, без почты.
3. Обычный браузер (не телеграм) → экран входа с почтой как раньше.
