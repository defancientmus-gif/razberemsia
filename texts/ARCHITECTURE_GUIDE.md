# Часть 1. Философия — читать первой

Без этой части остальное превращается в карго-культ: скопировали код, получили другое
приложение. Технические решения ниже **выведены** из этих принципов, а не наоборот.

### 1. Агент решает, а не сообщает

Не «у тебя конфликт в 15:00» → а «перенёс на 16:30, напомню за 20 минут, ок?».
Отсюда в коде: `options` всегда `[]`, никаких кнопок-вариантов, `CLARIFY` почти мёртв.
Агент делает лучшее предположение и говорит, что сделал и как поправить одним словом.

**Для Гили:** это ровно ваш пункт «Одно окно вместо кнопок разделов. Пишешь, раздел
определяю я». Вы уже идёте туда — просто доведите: не спрашивать, а класть и показывать куда.

### 2. Не говорим НЕТ

Всегда находим позитивный исход. Единственное исключение — реальный вред жизни.
Ошибка с добрым тоном лучше правильного ответа с холодным.

### 3. Простота > функциональность

Если фича требует объяснения — она сделана неправильно. Каждая новая кнопка/сущность —
это долг (из `ФИЛОСОФИЯ.md` дома: «не создавай магию»).

**Совпадение с вашей планкой:** ваш пункт 4 «Текст на языке человека. Спросил — виноват
экран» — это то же самое правило с другой стороны. Мы его формулируем как
«Это поймёт человек, который первый раз держит смартфон?».

### 4. Уменьшаем хаос, а не выполняем команды

Формулировка Жени — описание боли, а не ТЗ. Странная буквальная трактовка = сигнал
перечитать смысл. Улучшать реализацию можно, менять цель — нет.

### 5. Правда важнее согласия

Плохую архитектуру называть плохой. Ваш аудит с цифрами 40% и 47% — образцовое применение
этого принципа, честно и в лицо. Мы такое уважаем и отвечаем тем же (см. поправку выше).

### 6. Ошибка — недостаток механизма, а не повод искать виноватого

Отсюда все «предохранители» в коде ниже: телеметрия, видимые индикаторы, тесты.

# Часть 2. Быстрый запуск — с нуля до живого приложения

Наш стек намеренно тупой и живучий. Ни одной сборки, ни одного npm-пакета в рантайме.

```
index.html      вёрстка + весь CSS инлайном
js/app.js       вся логика (~7400 строк, один файл)
js/vendor/*.js  вендоренные библиотеки (НЕ CDN — см. 3.4)
sw.js           service worker, единственный источник версии
manifest.json   PWA
supabase/functions/ai/index.ts   мозг (Edge Function, Deno)
supabase/migrations/*.sql        схема БД
deploy.sh       весь деплой фронта одной командой
```

### Шаг 1. Хостинг — GitHub Pages

Репозиторий → Settings → Pages → Deploy from branch `main`, папка `/root`.
Всё. Пересборка сама за ~1 минуту после пуша. Бесплатно, без CI, без конфигов.

### Шаг 2. База — Supabase

1. Создать проект, забрать `URL` и `anon key` (публичный, его можно класть в клиент).
2. Вход: Auth → Email OTP (код на почту, без пароля — для нетехнарей это решает всё).
3. Таблица состояния + **обязательно RLS**, иначе данные видны всем:

```sql
create table if not exists user_state (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  notes      jsonb default '[]'::jsonb,
  updated_at timestamptz default now()
);
alter table user_state enable row level security;
create policy "own state select" on user_state for select using (auth.uid() = user_id);
create policy "own state insert" on user_state for insert with check (auth.uid() = user_id);
create policy "own state update" on user_state for update using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

4. Для мгновенной синхронизации (Часть 3.2):
```sql
alter table user_state replica identity full;
alter publication supabase_realtime add table user_state;
```

**У Гили это уже есть** — `gili_notes` живёт в той же базе, политики свои, realtime в облаке
подключён (`sb.channel('гили').on('postgres_changes'…)`). Шаг можно пропустить.

### Шаг 3. Мозг — Edge Function

```bash
supabase login && supabase link --project-ref <ref>
supabase functions deploy ai --no-verify-jwt     # Docker НЕ нужен, грузит исходник
```
Секреты (Dashboard → Edge Functions → Secrets): `ANTHROPIC_API_KEY` и что нужно ещё.
`--no-verify-jwt` — функция сама проверяет токен внутри.

### Шаг 4. Деплой одной командой

```bash
./deploy.sh "что сделано"
```
Внутри: поднять версию в `sw.js` → `node --check` (синтаксис; ошибка = деплой отменён) →
отметка в SNAPSHOT → `git add` только нужного → commit → push.

**Три полосы деплоя раздельные, это главная грабля:**

| Меняешь | Чем | Куда |
|---|---|---|
| фронт | `./deploy.sh` | GitHub Pages |
| мозг | `supabase functions deploy ai` | Supabase Edge |
| схему БД | Dashboard → SQL Editor | Postgres |

`deploy.sh` **не коммитит** Edge и миграции. Правка мозга может уехать на прод и остаться
вне гита — мы на этом попались с GUIDE. После деплоя Edge — руками `git add` + коммит.

# Часть 3. Интересные решения

## 3.1. Самозаточка — то, чего вам не хватает

**Идея:** ИИ не работает вместо алгоритма — ИИ **перетачивает правила** алгоритма.
Экономика разворачивается: чем больше пользуются, тем реже нужна модель.

Три шага. У вас готовы два, третьего нет — вот он.

```
1. Правила = данные       у вас есть: ЦЕНТР/правила-разбора.json
2. Копим промахи          у вас есть: окно/промахи.py → ЦЕНТР/ПРОМАХИ.md
3. Изредка ОДИН запрос:   ← ЭТОГО НЕТ. Ниже — рабочий код.
   правила + промахи → модель → новые правила
```

### Клиент: когда точить (у нас `js/app.js`)

```js
const _RULES_MIN_EXAMPLES=30;   // накопилось столько промахов…
const _RULES_MIN_DAYS=7;        // …или прошла неделя (и есть хотя бы 8)
const _RULES_BOOTSTRAP_MIN=20;  // стартовая генерация словаря с нуля

let _sharpenTriedThisSession=false;
async function _maybeSharpenTagRules(){
  if(_sharpenTriedThisSession||!cloudAllowed()||!navigator.onLine)return;
  _sharpenTriedThisSession=true;           // не чаще раза за сессию
  const rules=getTagRules(), fresh=_getTagExamples();
  if(!rules){                               // ещё нет словаря — родить из размеченного
    const seed=getNotes().filter(n=>(n.aiTags||[]).length)
      .slice(0,80).map(n=>({t:(n.title+' '+n.body).slice(0,140),a:n.aiTags}));
    if(seed.length<_RULES_BOOTSTRAP_MIN)return;   // мало данных — пусть копится
    return _tuneRulesRequest(null,seed);
  }
  const days=(Date.now()-(rules.updatedAt||0))/86400000;
  if(fresh.length>=_RULES_MIN_EXAMPLES||(days>=_RULES_MIN_DAYS&&fresh.length>=8))
    await _tuneRulesRequest(rules,fresh);
}
// запуск: тихо в фоне через 9 сек после входа — не мешать старту
setTimeout(_maybeSharpenTagRules, 9000);
```

Промпт «оптимизатор правил» + **обязательная санитизация ответа** — правила едут прямо
в рабочий словарь, доверять сырому ответу модели нельзя:

```ts
const prompt = `Ты оптимизатор правил классификации.

// санитизация: лимиты, нижний регистр, отсев мусора
Object.keys(parsed.tags).slice(0,30).forEach(tag=>{
```

## 3.2. Синхронизация: одна память, мгновенно

Ваш аудит: «две памяти… любая функция поверх них будет работать по-разному». Согласен —
и это лечится не «починить нерв», а сменой модели данных.

### Local-first: localStorage — правда, облако — синхронизация

Приложение **никогда не ждёт сеть**. Пишем локально → рисуем сразу → облако догоняет в фоне.
Отсюда: работает в самолёте, мгновенный старт, сеть не роняет UX.

### Три слоя доставки (по убыванию скорости)

```js
// 1. broadcast — устройство САМО кричит «я сохранил» (мгновенно, не ждёт БД)
_realtimeChannel.send({type:'broadcast',event:'saved',payload:{at:updated_at}});

// 2. postgres_changes — пассивно, если broadcast не долетел
.on('postgres_changes',{event:'UPDATE',schema:'public',table:'user_state',
     filter:'user_id=eq.'+CU.id}, () => {_lastPullAt=0;_pullCloudIfStale();})

// 3. подстраховка опросом + события жизни приложения
setInterval(()=>{ if(document.visibilityState==='visible') _pullCloudIfStale(); },8000);
document.addEventListener('visibilitychange',…);   // вернулся в приложение
window.addEventListener('focus',…);                // вернулся в окно
window.addEventListener('online',()=>{ queueCloudSave(); … });  // появилась сеть
```

Плюс дебаунс `_lastPullAt` (не чаще раза в 3 сек), чтобы три слоя не устроили шторм.

**Для вас:** в облаке подписка уже есть. Не хватает того же на маке — тогда нерв
`com.dom.oblako` с его двумя минутами становится не нужен, а «две памяти» схлопываются
в одну без переписывания приложения.

### Мёрж перед записью — иначе устройства затирают друг друга

Наш самый дорогой баг (`rz-v407`). Заметки не синхронизировались **в обе стороны**, причём
`push` формально работал. Причина: сохранение заливало в облако сырой локальный срез.
Устройство B, не успевшее подтянуть свежую заметку с A, затирало её при своём сохранении.

Мёрж по `id`, победитель — по `updatedAt`. **У вас риск ниже** (строки-записи, а не один
JSON-блоб), но при правке существующей мысли с двух мест — тот же сценарий.

### Надгробия (tombstones) — чтобы удалённое не воскресало

Простой union при слиянии возвращает удалённое обратно с другого устройства. Лечится меткой
удаления с TTL 120 дней: `{tags:{"ключ":deletedAtMs}}`. Пересоздано позже метки → живёт.

### Видимый индикатор вместо тихой веры

У заметки, изменённой позже последнего успешного сохранения, рядом со временем — тихий
значок «облако не в сети». Пользователь видит правду, а не думает, что всё синхронно.
Это прямо ваш принцип «ни одной молчащей ошибки», только повёрнутый к человеку.

## 3.3. Экономия на модели: роутер профилей

Не слать 40 заметок, когда человек сказал «запиши хлеб». Профиль считают **regex на клиенте,
бесплатно и мгновенно**, до всякой сети:

| Профиль | Что кладём в запрос | Когда |
|---|---|---|
| `none` | ничего | «запиши/запомни…», напоминание без ссылок |
| `light` | ничего | вопрос-факт, пошаговое ведение |
| `notes` | 12 заметок × 140 символов | найти/открыть/удалить/продолжение разговора |
| `deep` | 40 × 400 + память + контекст | «что у меня», сводка, план |

Правило «один проход»: один вызов модели на ход, одно-два действия максимум, весь результат
сразу. Никаких цепочек вызовов.

**⚠️ Кириллица.** `\b` в JS-регулярках **не работает** с русскими словами. Границы только
руками: `(^|[^a-zа-я0-9_])(?:слово)(?=$|[^a-zа-я0-9_])`. Наступали трижды — в роутере,
в парсере напоминаний («утром/вечером» молча не срабатывали месяцами), и это же родня
вашего урока про «апи» внутри «записаться».

## 3.4. Офлайн и скорость запуска

- **Библиотеки вендорить локально, не CDN.** CDN без `crossorigin` даёт opaque response —
  service worker не может его закэшировать, и офлайн умирает молча. У вас `облако/supabase.js`
  лежит локально — правильно, так и держите.
- **Service worker: `skipWaiting()` без `clients.claim()`.** `claim()` захватывает страницу
  посреди загрузки и ломает первый запуск. Новый код подхватывается при следующем открытии —
  зато старт всегда мгновенный.
- **Кэш собирать по одному файлу:** `ASSETS.map(u=>cache.add(u).catch(()=>{}))` — один 404
  не рушит весь кэш.
- **Версия живёт в одном месте** (`sw.js`), её бампит скрипт деплоя. Бейдж версии в шапке
  приложения — видно, что реально приехало на телефон.
- **Мгновенный вход:** последний пользователь в `localStorage`, приложение стартует сразу,
  сессия проверяется в фоне. ⚠️ Цена: устройство может считать себя залогиненным при мёртвом
  токене (наш баг — телефон молча стоял 5 дней). Лечится индикатором из 3.2.

### Очередь офлайн-записей — то, что записано без сети, обязано долететь

Это главное в офлайне, и одного кэша для него мало. Правило: **пишем локально → рисуем
сразу → облако догоняет само.** Пользователь никогда не ждёт сеть и никогда не теряет запись.

```js
// 1. Любая запись сначала в localStorage, и только потом (с дебаунсом) в облако
function writeJson(key,value){
  localStorage.setItem(scopedKey(key),JSON.stringify(value));
  queueCloudSave();                     // не ждём результата, не блокируем UI

// 2. Очередь: во время загрузки не пушим, а ставим отметку «надо будет»

const _finish=()=>{CLOUD_LOADING=false;
  if(CLOUD_SAVE_PENDING){CLOUD_SAVE_PENDING=false;queueCloudSave();}};

// 3. Сеть вернулась: СНАЧАЛА отдать своё, ПОТОМ забирать чужое
window.addEventListener('online',()=>{
  queueCloudSave();                     // накопленное офлайн — вперёд
  _lastPullAt=0;
  if(CLOUD_READY_UID!==CU?.id) loadCloudData().then(()=>loadAll());  // стартовали без сети
  else setTimeout(_pullCloudIfStale,1500);
});

// 4. Догон: если локально записей БОЛЬШЕ, чем в облаке — significa офлайн-хвост, пушим обратно
if(merged.length>data.notes.length) queueCloudSave();
```

Четыре правила, без которых это ломается:

1. **Порядок при возврате сети — push раньше pull.** Иначе облако перезапишет то, что человек
   написал в самолёте, и запись исчезнет.
2. **Мёрж перед записью обязателен** (см. 3.2) — офлайн-хвост сливается с чужими правками
   по `id`, победитель по `updatedAt`. Без этого офлайн-устройство затрёт всё чужое.
3. **Ошибка сохранения — не молчит.** `if(navigator.onLine) showToast('Не удалось сохранить')`,
   плюс тихий значок «ещё не в облаке» у самой записи (3.2). Иначе человек верит, что всё улетело.
4. **Ничего не удалять до подтверждения.** Локальная запись живёт, пока облако не подтвердило
   приём; удаления — через надгробия, а не физическим стиранием.

### Почему это же переживает VPN

У Жени это отдельная боль — под VPN половина приложений отваливается. Наши три причины
живучести, все три бесплатные:

- **Ни одного стороннего домена.** Библиотеки вендорены, шрифты локальные, аналитики нет.
  Единственный внешний адрес — свой Supabase. Чем меньше доменов, тем меньше поводов отвалиться.
- **Service worker НЕ перехватывает кросс-доменное:**
  `if(!url.startsWith(self.location.origin)) return;` — API-запросы идут мимо кэша и честно
  возвращают свои ошибки. Если перехватывать всё подряд, под VPN получите зависшие запросы
  и невозможность понять, что происходит.
- **Cache-first для своих файлов.** Медленный или дёргающийся канал не влияет на запуск:
  интерфейс поднимается из кэша мгновенно, сеть нужна только для догона данных.

## 3.5. Уведомления (ваш открытый пункт)

Готовое к переносу: таблица подписок + серверный отправщик по расписанию.

```sql
create table if not exists push_subscriptions (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references auth.users(id) on delete cascade not null,
  endpoint text not null, p256dh text not null, auth text not null,
  unique(user_id, endpoint)
);
alter table push_subscriptions enable row level security;
create policy "own subs" on push_subscriptions for all using (auth.uid()=user_id) with check (auth.uid()=user_id);
```
В service worker — обработчики `push` и `notificationclick`; отправку дёргает `pg_cron`
раз в минуту в Edge Function. Детали и SQL — `supabase/migrations/20260520_push_notifications.sql`.

⚠️ На айфоне работает только для приложения, добавленного на домашний экран, и разрешение
даёт человек руками — вы это уже отметили в NEXT, подтверждаю.

## 3.6. Голос — ответ на ваш вопрос «чинить, выключать или оставить?»

**Выключайте локальные модели. 680 МБ не нужны.**

Родной `SpeechRecognition` браузера слышит **лучше** серверных Yandex и Whisper (проверено
у нас на живой диктовке), стоит 0 рублей, не требует ни моделей, ни сети до своего сервера:

```js
const SR = window.SpeechRecognition || window.webkitSpeechRecognition;
rec.lang='ru-RU'; rec.continuous=true; rec.interimResults=false;
rec.onerror = e => { if(e.error==='no-speech') return; … };  // молчание — не ошибка
rec.onend = () => { /* SR останавливается САМ — собирать результат здесь */ };
```

Иерархия: `SpeechRecognition` → (если нет) запись в WAV → сервер (Yandex → Groq).
Полностью, со всеми граблями — [[VOICE_STT_PROMPT.md]].

⚠️ Ваша грабля «окно падало на распознавателе WebKit» — это про **WKWebView в обёртке
Пульт.app**, там SR действительно неполноценный. Но в облаке (Safari/Chrome на телефоне)
SR живой. Поэтому предлагаю: голос в облаке — включить бесплатно, в окне на маке — оставить
выключенным. Это снимает треть кода сервера и при этом не теряет функцию там, где она нужнее.

## 3.7. Телеметрия — иначе прод не отладить

Одна строка после каждой тяжёлой операции:

```js
console.info('[rz] voice timing', {encode_ms, roundtrip_ms, provider, audio_sec, wav_kb});
```
Ею мы поймали два бага, которых иначе не увидели бы: iOS писал звук на 48000 Гц вместо
запрошенных 16000 (сервер слышал «кашу»), и медленный провайдер распознавания.

**Ваш пункт «журнал сбоев вместо молчания» — это то же самое, и он у вас первым в очереди.
Правильно. Делайте его раньше всего остального.**
