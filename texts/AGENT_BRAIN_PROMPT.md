# Промт «мозга» — голосовой агент, который решает, а не переспрашивает

> Четвёртый переносимый промт (комплект: [[TECH_PROMPT.md]] система · [[GLASS_STYLE_PROMPT.md]] визуал ·
> [[VOICE_STT_PROMPT.md]] слух · этот — мозг). Описывает архитектуру принятия решений агента
> с точными правилами из прода. Источники: `supabase/functions/ai/index.ts` (action `agent_query`),
> `js/app.js` (`_agentRoutingPlan`, `_processAgentQuery`).

---

## Философия (определяет ВСЕ технические решения ниже)

**Агент не сообщает о проблеме — он её решает и докладывает.** Не «у тебя конфликт в 15:00»,
а «перенёс на 16:30, ок?». Отсюда три железных следствия:

1. **ДЕЙСТВУЙ, НЕ СПРАШИВАЙ.** Никаких уточняющих вопросов и кнопок-вариантов (`options` всегда `[]`).
   Лучшее разумное предположение → сразу действие → тёплый `response` «что сделал и как поправить одним словом».
2. **Не говорим НЕТ.** Ошибиться с добрым тоном лучше, чем правильно переспросить холодным.
3. **CREATE_NOTE — действие по умолчанию.** Есть хоть какой-то текст → это заметка.
   Непонятный ввод НИКОГДА не теряется.

---

## Архитектура: две половины мозга

```
Фраза пользователя
   │
   ▼
[КЛИЕНТ] Router — детерминированный, бесплатный, мгновенный
   │  regex-детекторы → профиль контекста: none / light / notes / deep
   ▼
[СЕРВЕР] Один вызов LLM — весь интеллект в одном промпте
   │  дерево решений → JSON {actions, response, options:[]}
   ▼
[КЛИЕНТ] Исполнение actions + тёплый ответ (текст/голос)
```

Правило «один проход»: ОДИН запрос к LLM на ход, одно-два действия максимум,
весь результат сразу (GUIDE отдаёт все шаги в том же ответе). Никаких цепочек вызовов.

---

## Половина 1 — клиентский Router (профили контекста)

Зачем: не слать 40 заметок, когда человек сказал «запиши хлеб». Профиль решают
regex-детекторы ДО обращения к серверу. Клиент — источник правды (есть smoke-тест).

| Профиль | Что кладём в промпт | Когда |
|---|---|---|
| `none`  | ничего | быстрая запись («запиши/запомни…»), напоминание без ссылок на прошлое |
| `light` | ничего (короткий ответ) | вопрос-факт, GUIDE (чужие заметки не нужны ведению) |
| `notes` | 12 заметок × 140 символов | найти/открыть/удалить/прочитать, продолжение разговора |
| `deep`  | 40 × 400 + память + контекст приложения | «что у меня», сводка, план |

Детекторы (полные списки слов — в `_agentRoutingPlan`):
- `continuation` — «это/ту/её/последнюю/здесь/тогда…» → нужна история + заметки
- `quickWrite` — НАЧИНАЕТСЯ с «запиши/запомни/создай/добавь/сохрани» И нет поисковых слов → none
- `reminder` / `reminderNeedsNotes` — «напомни…»; со ссылкой «что я хотел» → notes
- `destructive` — «удали/сотри/отмени/убери» → notes (нужно видеть что удалять)
- `broadNotes`/`plan` — «сводка/что у меня/план/маршрут» → deep
- `guide` — «как мне…/помоги войти…/не получается…» → light (приоритетнее deep-слов нет)

**⚠️ Грабля кириллицы:** `\b` в JS-regex НЕ работает с русскими словами. Границы — только
самодельные: `(^|[^a-zа-я0-9_])(?:слово)(?=$|[^a-zа-я0-9_])` (функции `_agentRouteWord`/`_agentRouteStarts`).
Наступали дважды (роутер, парсер напоминаний).

## Половина 2 — серверный промпт (скелет, проверенный продом)

Порядок блоков в промпте (каждый существует, потому что без него агент ошибался):

1. **Время и пояс клиента** — клиент шлёт `clientNow`+`clientTz`, сервер форматирует в
   локаль пользователя. Без этого «завтра» на сервере в UTC — не «завтра» пользователя.
2. **ROUTER-блок** — сообщаем модели профиль: «none/light → простое действие, не делай сводку».
3. **Список ДОСТУПНЫХ ДЕЙСТВИЙ** — интент + краткое «когда» (≈16 интентов).
4. **ДЕРЕВО ВЫБОРА** — нумерованный список «пройди сверху вниз, бери ПЕРВОЕ что подошло,
   ровно ОДНО действие»: 1 застрял-и-просит-помочь→GUIDE · 2 записать→CREATE_NOTE ·
   3 ко времени→SET_REMINDER · 4 удалить→DELETE_* · 5 обзор всего→DAILY_BRIEFING ·
   6 план→MAKE_PLAN · 7 поиск по теме→FIND_NOTES · 8 факт-вопрос→QUESTION.
   Это главное лекарство от «агент путается в своих инструментах».
5. **Формат ответа** — строгий JSON `{actions:[{intent,params}], response, options:[]}` без markdown.
6. **Параметры по действиям** — таблица `интент → {поля}` с дефолтами (`noteIndex:0` = последняя).
7. **Блоки правил-граблей** (см. ниже).
8. **Контекст по профилю**: заметки `[индекс][дата][📁раздел] «title» 🔔время — body`,
   история 4 хода, «📍 Где сейчас», разделы пользователя.

### Правила-грабли (каждое — из реальной ошибки прода)

- **Папки — только по явному слову** «папку/раздел/категорию/тег». «Напомни про врача» →
  НЕ папка «врач», а SET_REMINDER. Это была самая частая и самая бесящая ошибка.
- **DAILY_BRIEFING vs FIND_NOTES**: «сводка за день» — это ОБЗОР (briefing), не поиск.
  FIND_NOTES только при конкретной теме. В промпте — примеры обеих ошибок дословно.
- **SET_RECURRING**: «каждые 2 часа» → полный суточный ритм слотов 08:00–22:00,
  НЕ отсчёт от текущего времени и НИКОГДА не несколько SET_REMINDER.
- **Плохое распознавание**: клиент шлёт топ-2 альтернативы SpeechRecognition —
  «если основной текст странный, пойми намерение по альтернативам». Совсем непонятно →
  CREATE_NOTE с тем что расслышал (не потерять ввод!).
- **История — только для явных продолжений** («это», «ту», «первую»). Новый самостоятельный
  запрос НЕ связывать со старым разговором. Иначе агент туннелится в прошлую тему.
- **«Здесь/сюда/эта папка»** — только эти слова активируют текущий экран. Без них
  местоположение пользователя не меняет смысл запроса.
- **Не придумывай содержимое** — в title/body только слова пользователя.
- **CLARIFY почти мёртв**: единственный случай — назван раздел и НИЧЕГО больше
  («запиши в финансы» и всё) → мягкая строка «Открыл Финансы — что записать?», без кнопок.

### GUIDE — агент-проводник (первый «доер»)

Для «как войти в госуслуги» / «не могу зайти в почту»: 3–7 шагов, ОДНО действие на шаг,
язык для человека, впервые держащего смартфон, все шаги в одном ответе. Не факт-ответ
(это QUESTION) и не план по заметкам (это MAKE_PLAN) — в дереве стоит ПЕРВЫМ, иначе тонет.

## Клиентская обвязка (UX доверия)

- **Живая карточка сразу**: «Разбираюсь…» появляется в момент запроса (видно, что услышал),
  и та же карточка плавно превращается в ответ — без вспышки/пересоздания DOM.
- **Таймаут 30с** + за 5с до него тост «Агент думает… [Ещё 30 сек]» — долгий запрос
  не умирает молча и не висит вечно.
- **История**: 4 хода, TTL 15 минут (пауза → чистый лист). Хранится на клиенте, в промпт
  идёт только при continuation-словах.
- Содержательные ответы не автозакрываются; ошибка/таймаут гасят карточку с тостом.

---

## Экономика (курс «алгоритмы вместо ИИ», см. SELF_TUNING)

- Профили роутера режут контекст ДО модели: «запиши хлеб» не возит 40 заметок.
- «Один проход» режет число вызовов: всё в одном ответе, без цепочек.
- Локальный классификатор тегов забирает рутину у `analyze` (самозаточка `tune_rules`).
- Следующие кандидаты: локальный парсер дат (каждое «напомни завтра в 10» ходит к LLM
  только за датой), дневной лимит запросов на пользователя (предохранитель ключа).

## Чек-лист переноса в новый проект

1. Сначала философия: список «агент решает, не спрашивает» + действие-по-умолчанию,
   которое никогда не теряет ввод.
2. Клиентский роутер с профилями контекста + smoke-тест роутера в CI (клиент — источник правды).
3. Дерево выбора действий нумерованным списком, «бери ПЕРВОЕ», ровно одно действие.
4. Строгий JSON-контракт, `options:[]` навсегда.
5. Время+пояс клиента в промпт с первого дня.
6. Каждую реальную ошибку агента — в промпт дословным примером «ОШИБКА: … → НЕ …, а …».
7. Кириллица: границы слов руками, `\b` не работает.
8. Живая карточка + таймаут с продлением — доверие дороже фич.
