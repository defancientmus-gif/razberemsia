# Правила

## Философия кода (читать всегда)

**Не создавать костыли.** Если решение требует обходного пути — это сигнал что архитектура неверна. Переделываем правильно.

**Не упрощать себе жизнь за счёт качества.** Цель — максимально корректное, плавно работающее приложение. Никаких «пока сойдёт» и «потом переделаем».

**Роутер агента — интуитивный маршрут, не набор регулярок.** Каждое правило должно отражать реальное намерение пользователя, быть проверено smoke-тестом и не конфликтовать с другими правилами.

**Фикс не закрыт пока не задеплоен и не проверен на живом устройстве.**

## Перед работой

1. Читать `texts/README.md`.
2. Читать `texts/ROUTER.md`.
3. **Читать `texts/SNAPSHOT.md`** — реальное состояние деплоя, версии, незакоммиченное.
4. Читать файлы только из маршрута задачи.
5. Проверять `git status --short --branch`.
6. Не трогать чужие/untracked изменения без прямой просьбы.

## Визуальные изменения — обязательно

Любое изменение дизайна, логотипа, кнопки, цвета, шрифта, размера:

1. **Проверить файл до вставки:** SVG-логотип не должен быть больше ~50 KB. Если больше — внутри скорее всего растр (PNG в base64), а не вектор. Спросить пользователя.
2. **После вставки — скриншот.** Открыть превью, сделать скриншот, показать пользователю ДО git commit.
3. **Не деплоить визуал вслепую.** Даже если HTML написан правильно — реальный вид может не совпадать с задумкой.

## Самоустановки Claude

- **Версия CACHE** — читать только из `sw.js` строку `const CACHE`. Не доверять CONTEXT.md или SNAPSHOT — они могут отстать.
- **Дубли функций** — перед правкой любой функции grep по обоим: `index.html` + `js/app.js`. Кодекс дублирует код.
- **Inline-скрипты** — после правки JS проверить, нет ли конкурирующей реализации в `<script>` в конце `index.html`.
- **Supabase function** — если `git status` показывает `M supabase/functions/ai/index.ts`, разобраться ДО правки.
- **Кодекс в prototypes/** — интегрировать его код только после ревью, не копировать вслепую.
- **Деплой через `./deploy.sh`** — не вручную, чтобы SNAPSHOT обновлялся автоматически.

## Runtime

- Не создавать новые рабочие HTML-файлы с версиями в названии.
- Рабочая входная точка всегда `index.html`.
- Если менялись `index.html`, `js/app.js`, `sw.js` или кэшируемые ассеты, поднять `CACHE` в `sw.js`.
- Версия в интерфейсе должна соответствовать реальному деплою.
- Не считать «работает локально» достаточной проверкой для PWA.

## Supabase

- Не класть `service_role` key в клиент.
- Не отключать RLS.
- Не класть Anthropic/OpenAI/API keys в клиент.
- Все AI-запросы идут через Supabase Edge Function.
- Любая схема: сначала SQL/migration и fallback, потом клиент.

## AI и UX

- Заметки и облако важнее AI-слоя.
- AI не меняет исходный текст без подтверждения.
- Показывать одну полезную подсказку за раз.
- Не добавлять самодеятельность в визуал без задачи на дизайн.
- Не использовать тяжёлые анимации/blur на постоянно видимых элементах.

## Деплой

Быстрый деплой — одна команда:

```bash
./deploy.sh "описание правки"
```

Скрипт делает сам: bump CACHE в `sw.js` → `git add` изменённых файлов → commit → push.

Вручную (если скрипт недоступен):
1. Поднять `CACHE` в `sw.js`: `rz-vX` → `rz-v(X+1)`
2. `git add index.html js/app.js sw.js` — только нужные файлы
3. `git commit -m "описание"`
4. `git push origin HEAD:main`

После пуша на телефоне: потянуть вниз для reload или закрыть/открыть. Если не обновилось — Настройки → Safari → Очистить кэш.

Проверка SW: DevTools → Application → Service Workers → версия кэша = новая.

## Проверки

- `node --check js/app.js`
- Проверка inline-скриптов из `index.html`
- `node scripts/smoke-agent-router.mjs` после правок голосового агента/маршрутизатора
- `texts/TEST_GRID.md` - живая сетка для Mac/iPhone/Windows
- Живой сценарий: вход -> загрузка -> новая заметка -> обновление -> заметка осталась.
