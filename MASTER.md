## Суть проекта

`Разберёмся` — спокойный цифровой помощник и PWA-заметки для людей, которым сложно или тревожно пользоваться современными сервисами.

Главный принцип:

> Если человек чего-то не понимает — это нормально. Разберёмся.

Тон интерфейса и кода должен поддерживать:

- простоту;
- человечность;
- спокойствие;
- безопасность;
- постепенное развитие без лишнего усложнения.

## Текущая проблема

Авторизация по почте работает нестабильно.

Симптомы пользователя:

1. На ПК после клика по письму страница сначала показывает форму ввода почты, потом через несколько секунд может авторизоваться.
2. На iPhone форма остаётся на экране.
3. При отправке ссылки на iPhone показывается ошибка:

   `Проверьте адрес почты и попробуйте ещё раз.`

4. В поле на скриншоте видно `defancientmus@gmail.co`, хотя пользователь вводит `defancientmus@gmail.com`. Возможно, это визуальное обрезание поля, но нужно проверить.
5. Кнопка выхода из личного кабинета раньше работала нестабильно. Контекстное меню выходило нормально. Последний патч уже сделал `doSignOut` асинхронным, но надо перепроверить.

## Вероятные причины

Проверить спокойно, по порядку:

1. **PWA/service worker cache.**
   На телефоне может открываться старая версия `index.html`, несмотря на свежий деплой. Нужно увеличить кэш в `sw.js` при деплое и убедиться, что новая версия реально загружается.

2. **iOS Safari и PWA имеют отдельное хранилище.**
   Если пользователь кликает magic link в Gmail/почте, сессия может попасть в Safari или встроенный браузер почты, а не в установленную PWA. Для теста сначала чинить вход в Safari, потом уже отдельно думать про установленную PWA.

3. **Supabase magic link redirect.**
   Сейчас `initAuth()` явно обрабатывает только `?code=` через:

   ```js
   sb.auth.exchangeCodeForSession(location.href)
   ```

   Нужно проверить, не приходит ли Supabase на iPhone через hash-fragment (`#access_token=...`) или через другой формат. Supabase-js обычно сам это подхватывает, но текущая логика может слишком рано показывать форму.

4. **Задержка `getSession()`.**
   На медленном телефоне сессия может появляться не сразу. Нужен аккуратный режим ожидания входа, чтобы форма не мигала и не вводила пользователя в заблуждение.

5. **Ошибка отправки письма.**
   Нужно вывести/посмотреть реальную ошибку Supabase в консоли или временно добавить безопасную отладку через `?debug=1`, не показывая секретов.

6. **Supabase настройки.**
   Пользователь уже добавлял redirect:

   `https://defancientmus-gif.github.io/razberemsia/`

   Нужно убедиться, что в Supabase настроены:

   - Site URL: `https://defancientmus-gif.github.io/razberemsia/`
   - Redirect URL: `https://defancientmus-gif.github.io/razberemsia/`
   - Email provider enabled.
   - Если включены ограничения/SMTP/rate limit, ошибка может быть из-за лимита отправок.

## Что сделать следующим заходом

### 1. Сначала изучить текущее состояние

Команды:

```powershell
git status --short
rg -n "SUPABASE|supabase|signInWithOtp|exchangeCodeForSession|getSession|onAuthStateChange|doSignOut|local" index.html
rg -n "rz-v|CACHE|index.html" sw.js
```

### 2. Исправить auth flow

Цель: при открытии страницы после magic link не показывать сразу форму ввода почты. Сначала показать спокойный статус `Проверяем вход...`, дождаться Supabase-сессии, и только потом показать форму, если сессии точно нет.

Рекомендованный подход:

- создать Supabase client с явными auth options:

```js
supabase.createClient(SUPABASE_URL,SUPABASE_ANON_KEY,{
  auth:{
    detectSessionInUrl:true,
    persistSession:true,
    autoRefreshToken:true,
    flowType:'pkce'
  }
})
```

- в `initAuth()`:
  - включить checking state;
  - обработать `?code=`;
  - если URL содержит auth hash/token, дать supabase-js время сохранить сессию;
  - сделать короткий retry-loop `getSession()` на 3-5 секунд;
  - только после этого показывать форму.

### 3. Исправить/проверить поле email на телефоне

Проверить CSS:

- ширина input должна занимать всю карточку;
- текст не должен визуально обрезать `.com`;
- добавить `autocomplete="email"`, `inputmode="email"`, `autocapitalize="none"`, `spellcheck="false"` если ещё не стоит;
- если поле всё равно выглядит обрезанным, расширить карточку/поле на мобильном.

### 4. Улучшить ошибку отправки ссылки

Сейчас пользователь видит слишком общий текст. Нужно аккуратно различать:

- неправильная почта;
- rate limit;
- email provider disabled;
- redirect URL not allowed;
- network/CORS;
- Supabase project/settings problem.

Можно добавить временный debug-вывод только при `?debug=1`, например маленький блок с последней ошибкой Supabase. Не показывать ключи и токены.

### 5. Проверить выход

Проверить все кнопки, которые вызывают `doSignOut`.

Нужно, чтобы:

- выход очищал Supabase session;
- возвращал на auth screen;
- не оставлял пользователя в приложении;
- не ломал меню.

### 6. Проверить cloud sync

Если вход заработал, проверить:

- создать заметку на ПК;
- открыть тот же аккаунт на телефоне;
- заметка появляется после входа;
- изменения сохраняются в `public.user_state`;
- RLS не даёт читать чужие строки.

Если таблица ещё не создана, попросить пользователя выполнить `supabase.sql` в Supabase SQL Editor.

## Деплой

Обычный деплой:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\deploy.ps1 "fix supabase auth"
```

`deploy.ps1` сам увеличивает кэш `sw.js`, коммитит и пушит в `main`.

Если GitHub Pages использует `master`, после деплоя может понадобиться синхронизация `master` с `main` через merge commit без force push.

## Как объяснять пользователю

Писать простым языком.

Важное объяснение для iPhone:

> Вход на ПК не входит автоматически на телефоне. На каждом устройстве нужно открыть ссылку из письма. На iPhone Safari, Gmail-встроенный браузер и PWA-ярлык могут хранить вход отдельно, поэтому сначала проверяем вход именно в Safari, а потом доводим PWA.

Не обвинять пользователя в ошибках. Тон: спокойно, по-человечески, без технического давления.
