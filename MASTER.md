## Жёсткие правила

- Не менять код, если пользователь просит обновить только промты/документы.
- Не возвращать локальный/dev-вход в публичную версию.
- Не добавлять обходы авторизации.
- Не хранить приватные ключи Supabase в `index.html`.
- Не создавать новые рабочие HTML-файлы с версиями в названии.
- Рабочий HTML всегда `index.html`.
- Старые HTML-копии хранить только в папке `1`.
- Не делать длинные PowerShell-команды, которые массово переписывают HTML через regex. Защитник Windows уже ругался на похожий паттерн как на `Trojan:Win32/ClickFix.DQ!MTB`.
- Для ручных правок использовать `apply_patch`.
- Не удалять пользовательские изменения без явной просьбы.

## Текущее устройство авторизации

Сейчас логика не magic link, а email OTP:

1. Пользователь вводит почту.
2. `sendEmailLink()` вызывает:

```js
sb.auth.signInWithOtp({ email, options:{ shouldCreateUser:true } })
```

3. Supabase отправляет 6-значный код.
4. Пользователь вводит код в `step-code`.
5. `verifyOtpCode()` вызывает:

```js
sb.auth.verifyOtp({ email:_otpEmail, token:code, type:'email' })
```

6. После успешной сессии `enterUser()` загружает Supabase-данные и показывает приложение.

Важно: не путать текущий OTP-режим со старым magic link через redirect.

## Что проверять при проблемах входа

Если пользователь снова пишет, что вход не работает:

1. Убедиться, что открыта свежая версия, а не старый PWA-кэш.
2. Проверить `sw.js` cache name.
3. Проверить в Supabase:
   - Email provider включён;
   - Auth email OTP разрешён;
   - лимиты отправки не исчерпаны;
   - `supabase.sql` выполнен;
   - RLS включён и политики корректны.
4. Проверить, что письмо приходит именно с кодом, а не со старой ссылкой.
5. Проверить, что поле кода принимает только 6 цифр.
6. Проверить ошибки `otp send failed` и `otp verify failed` в консоли.
7. Для временной диагностики можно использовать `?debug=1`, если это уже есть в коде.

## Данные и безопасность

Supabase-таблица описана в `supabase.sql`.

Ожидаемая модель:

- таблица `public.user_state`;
- `user_id uuid primary key references auth.users(id)`;
- поля `notes`, `trash`, `history`, `name`, `updated_at`;
- RLS включён;
- пользователь может читать и писать только строку, где `auth.uid() = user_id`.

Не отключать RLS ради удобства.

## Деплой

Обычный деплой:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\deploy.ps1 "описание изменения"
```

`deploy.ps1` сам:

- работает из папки проекта;
- повышает cache name в `sw.js`;
- делает `git add -A`;
- коммитит;
- пушит в `main`.

Если GitHub Pages смотрит на `master`, после деплоя может понадобиться синхронизация `master` с `main` через merge commit без force push.
